# 异步任务编排

任务要拆成多个子节点、且子节点之间需要交换消息时使用。本 skill 规定组织方式，不点名任何一颗工具：谁能用什么、参数长什么样，由该节点那一跳的运行时契约与候选名单决定。

## 适用与不适用

- 适用：并行取证后汇总、多角色互评或辩论、分票统计、需要人工中途确认、兄弟互告后各自下派的流水。
- 不适用：单节点就能做完的任务；单轮并行取证——普通派生加子节点终局回报即可，不需要交换消息。

## 三条铁律

1. **等谁就写谁。** 节点停靠等待时必须声明它在等哪些节点。不声明不是"少写一个参数"，而是放弃全部活性保证：互相等待不会被识别成环，被等的节点结束或被暂停时也不会通知它。
2. **等齐用批次，等一个是停靠。** 停靠的语义是"任意一条消息唤醒"，它不等于等齐。要等全部子节点结束，用派生批次的回收语义，不要给每个子节点各停靠一次。
3. **跨子树要等，说明拓扑选错了。** 只有父节点、执行后代、同父兄弟之间能互相寻址；表亲与祖辈不可直连。结构如果需要跨分支等待，改由共同祖先转述，或重新分层。

## 选型

| 任务形态 | 结构 | 等待怎么声明 |
| --- | --- | --- |
| 并行取证、结果汇总 | 同批派生 N 个，批次回收 | 父节点不声明，用批次回收 |
| 多视角互评、辩论 | 同父兄弟常驻多轮 | 讨论者声明同级 id 列表；父声明各讨论者 id |
| 分票统计 | 同父兄弟各投一票 | 父声明投票者 id 列表，计票由父节点自己数 |
| 中途需要人工确认 | 单节点停靠 | 声明前门：等操作员是合法的无限等待 |
| 分批流水 | 兄弟互告后各自下派 | 每跳声明下一跳 |

## 各结构的组织要求

### 并行取证后汇总

一次派生整批，让批次回收去等全部结果。不要在批内让子节点依赖彼此的产出——同批子节点不保证先后，也读不到对方的中间结论。

### 多角色互评与辩论

父节点：

1. **一次派生、常驻多轮**：把 N 个讨论者放进同一次派生里一起建出来；父节点不要按轮次重建讨论者。讨论者自己的研究子节点不在此限。
2. **只发边界**：轮次开始、下一轮开始、进入终审三类消息。父节点不代转发言，不替讨论者拟定每轮质询目标；轮次话题可以给，具体攻击哪条证据由讨论者自己决定。
3. **轮次完成协议**：每个讨论者每轮结束向父节点发一条只含状态的消息（轮次、是否有新证据、是否已落盘）；父节点收齐本批 N 条后再发下一轮。不要用“等整批子节点都终局”当轮次 barrier——常驻讨论者只会在最终提交时终局。最终提交时可以让整批结果一起到达。
4. **终审**：父节点发停止信号，终审结论由父节点自己作为终局结果提交，不作为讨论发言。
5. 某讨论者暂停或失败时按常规的子节点处置通道处理；不要把缺失的轮次完成状态当成已完成。

讨论者：

1. **首轮独立**：发布首轮立场前不读、不向同级索取证据；首轮发布后必须直接质询。
2. **同级定位**：用本跳在场的节点关系视图找**执行同级**的节点；同级里的验收节点不可发。
3. **直接通信**：质询与回应都走节点之间的直接消息；要等对方时停靠，并声明在等谁。
4. **每轮状态**：每轮结束向父节点发一条只含状态的轮次完成消息；不要只写文件等父节点转述。
5. 发言与证据按任务约定追加式落盘；消息用于互动，文件用于审计。

### 分票统计

同父兄弟各投一票，父节点声明全部投票者并自己计票——运行时没有计票与法定人数原语，"满票"由提示词约定。投票者常驻时，父节点收到的第一条消息就会唤醒它，所以要么在提示词里写清"未满票时重新停靠"，要么让投票者投完一轮就终局。

### 评审团

同父兄弟互评可行，但判决权仍在父节点或验收节点手上：验收节点与被检验的执行节点一对一绑定，验收期间发给它的消息不唤醒它。不要设计成"多个评委独立合议后自行出结论"。

### 分批流水

兄弟节点互告进度后各自下派下一跳。跨分支依赖经共同祖先转述；转述意味着父节点是瓶颈，出现两跳以上转述通常说明该拆成两条独立任务。

## 被拒绝的停靠

停靠声明可能在提交时就被拒绝，逐条给出原因：目标不在本任务、目标已终态、目标发不了消息给你。三种都表示这个等待永远不会被满足——不要换一种写法重试同一地址；做完能做的，或换一个真的会回话的地址。

## 反模式

- 父节点每轮重新派生 8 个节点：得到 24 个轮次工人，不是 8 个常驻讨论者。
- 父节点把每轮攻击目标全写好：讨论者只执行，不讨论。
- 只让讨论者读文件、彼此不可见：没有直接通信。首轮独立只要求"发布前不读、不索取证据"。
- 在子节点提示词里写死通信工具名：工具名以该节点当跳契约为准，写死的名字不在场时，讨论者只会去试探和误判能力。
- 用定时唤醒轮询子节点是否还活着：声明等待后，被等节点结束或被暂停会主动通知你。
- 把正确性押在环检测上：互相等待会被打破，但方式是强制唤醒环里最浅的那个节点，不是报错返回。每个等待都要有明确的退出条件，例如轮次上限或终审信号。
- 把本 skill 全文复制进每个子节点的提示词。
