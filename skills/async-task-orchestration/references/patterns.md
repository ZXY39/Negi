# 子节点提示词模板

父节点复制后按本次任务填充。模板不点名工具：每处通信、停靠、派生都要求子节点先在本跳运行时契约里确认能力与参数。

## 并行取证

```text
你是本次任务的第 {i} 个取证分支，负责 {scope}。
【约束】只做 {scope} 内的事；不要等其他分支的结论，也不要索取它们的中间结果。
【派生】若你的分支有互不依赖的子问题，自行派生子节点；结果以子节点终局回报回来。
【交付】按 {deliverable_path} 落盘；提交时给出结论摘要与证据编号。
```

## 多角色互评与辩论（讨论者）

```text
你是本次讨论的第 {i} 位讨论者「{role}」，常驻第 {rounds} 轮。
【首轮】发布前不读、不向同级索取证据；按 {evidence_path} 落盘 R1。
【通信】先在本跳运行时契约里确认节点间直接通信的能力与参数，用它找同级并质询/回应；要等对方消息时停靠，并声明在等谁。
【轮次】每轮结束向父节点 {parent_id} 发一条只含状态的消息（轮次/是否有新证据/是否已落盘）；收到“进入终审”后停止质询并提交终局结果。
【派生】若你的分支有互不依赖的取证/分析子问题，自行派生子节点；可多级；结果以子节点终局回报回来。
【终止】{termination_rule}
【交付】{deliverable}
```

## 分票统计（投票者）

```text
你是本次评审的第 {i} 位投票者，负责从「{dimension}」维度判断。
【依据】只基于 {evidence_path} 里的事实判断；不要等其他投票者的结论。
【投票】按 {ballot_format} 把票发给父节点 {parent_id}，一票一条消息，正文含结论与依据编号。
【终局】投完即提交终局结果；收到父节点的补投要求时再开一轮。
```

父节点侧：声明全部投票者 id，自己计票；第一条消息就会唤醒你，未满票时需重新停靠。

## 中途人工确认

```text
你是本次任务的第 {i} 个分支，负责 {scope}。
【确认点】执行到 {checkpoint} 时停下来，把「已完成 / 待决定 / 选项与代价」整理成一条消息发给前门，然后停靠并声明在等前门。
【继续】收到操作员的答复后再往下做；答复到达前不要自行选择。
【交付】按 {deliverable_path} 落盘。
```

父节点侧：等操作员是合法的无限等待，不建环、也不会被反查打扰。

## 分批流水

```text
你是本批第 {i} 跳，负责 {stage}。
【输入】读 {upstream_path}；上游结论如有变化，同批兄弟会直接通知你。
【下派】完成后把交付路径与关键结论发给 {sibling_id}，并在需要时声明在等它。
【交付】按 {deliverable_path} 落盘；把你的输出路径写进消息正文，方便下游直接读取。
```

## 填写提示

- 占位符不填就派发，等于把结构决策交给子节点猜；至少填 scope、交付路径、终止条件三项。
- 子提示词里不要写死工具名：工具名以子节点当跳契约为准。
- 不要把本 skill 全文复制进每条提示词；只放该结构需要的那一段。
