# 多节点讨论/辩论编排

任务需要多个执行节点相互讨论、辩论或协作深入时使用。目标不是“多个独立分支并行做完再汇总”，而是同一批讨论者常驻多轮、直接互相质询，父节点只做边界与终审。

本 skill 只规定组织方式，不点名任何一颗工具：谁能用什么、参数长什么样，由该节点那一跳的运行时契约与候选名单决定。

## 适用与不适用

- 适用：多角色/多视角互相质询、回应、修正；讨论者需要常驻多轮；讨论者需要自己决定是否派生子节点做深入取证。
- 不适用：单轮并行取证、普通 map-reduce、验收节点裁决；这些用普通派生加子节点终局回报即可。

## 父节点

1. **一次派生、常驻多轮**：把 N 个讨论者放进同一次派生里一起建出来；父节点不要按轮次重建讨论者。讨论者自己的研究子节点不在此限，由它们在各自分支内按需派生。
2. **写清子提示词**：按下面模板写每个讨论者的 prompt；写清角色、轮次、终止条件、落盘位置。不要把本 skill 全文复制进每个 prompt。
3. **只发边界**：父节点向讨论者发三类消息：
   - 轮次开始：说明本轮话题与边界；
   - 下一轮开始：收齐本轮全部讨论者的“轮次完成”状态消息后再发；
   - 进入终审：要求讨论者停止质询并提交。
   父节点不代转发言，不替讨论者拟定每轮质询目标；轮次话题可以给，具体攻击哪条证据由讨论者自己决定。
4. **轮次完成协议**：每个讨论者每轮结束向父节点发一条只含状态的消息（轮次、是否有新证据、是否已落盘）；父节点收齐本批 N 条后再发下一轮。不要用“等整批子节点都终局”当轮次 barrier——常驻讨论者只会在最终提交时终局。最终提交时可以让整批结果一起到达。
5. **异常处置**：某讨论者暂停/失败时，按你对子节点的常规处置通道处理；不要把缺失的轮次完成状态当成已完成。
6. **终审**：父节点发“进入终审”的停止信号；终审结论由父节点自己作为终局结果提交，不作为讨论发言。
7. **控制动作**：暂停/恢复/终止仍走任务控制那条道，不要用讨论消息代替。

## 讨论者

1. **首轮独立**：发布首轮立场前不读、不向同级索取证据；只可发轮次就绪/状态。首轮发布后必须直接质询。
2. **同级定位**：用本跳在场的节点关系视图找**执行同级**的 `node_id`；同级里的验收节点不可发，自己的执行后代/后代验收节点按节点提示词的目标矩阵。
3. **直接通信**：用节点之间的直接消息能力发起质询/回应；要等对方时进入等待。用哪颗工具、参数形状与可发范围按当跳契约确认，不要按本 skill 的措辞去猜名字。
4. **每轮状态**：每轮结束向父节点发一条只含状态的轮次完成消息；不要只写文件等父节点转述。
5. **落盘**：发言与证据仍按任务约定落盘（追加式、编号唯一）；消息用于互动，文件用于审计。
6. **自行派生**：若你的分支有互不依赖的取证/分析子问题，自行派生子节点；结果以子节点终局回报回来。需要扩展范围时选允许扩展的执行档位，只做限定轮次时选只做必要动作的档位。
7. **收口**：收到父节点“进入终审”后停止质询，按任务要求提交终局结果；没有终止信号不要提前提交。

## 子节点提示词模板

父节点复制后按本次任务填充：

```text
你是本次讨论的第 {i} 位讨论者「{role}」，常驻第 {rounds} 轮。
【首轮】发布前不读、不向同级索取证据；按 {evidence_path} 落盘 R1。
【通信】先在本跳运行时契约里确认节点间直接通信的能力与参数，用它找同级并质询/回应；要等对方消息时进入等待。
【轮次】每轮结束向父节点 {parent_id} 发一条只含状态的消息（轮次/是否有新证据/是否已落盘）；收到“进入终审”后停止质询并提交终局结果。
【派生】若你的分支有互不依赖的取证/分析子问题，自行派生子节点；可多级；结果以子节点终局回报回来。
【终止】{termination_rule}
【交付】{deliverable}
```

## 反模式

- 父节点每轮重新派生 8 个节点 → 得到 24 个轮次工人，不是 8 个常驻讨论者。
- 父节点把每轮攻击目标全写好 → 讨论者只执行，不讨论。
- 告诉讨论者“互不可见”，或只让它们读文件 → 没有直接通信；首轮独立只需“发布前不读/不索取证据”。
- 在子节点提示词里写死通信工具名 → 工具名以该节点当跳契约为准，写死的名字不在场时讨论者只会去试探和误判能力，不会换来通信。
- 整批讨论者都只做必要动作档位且只给单轮任务 → 没有理由派生；需要扩展时选允许扩展的档位。
- 用“等整批子节点终局”当轮次完成的等待 → 常驻讨论者不终局，轮次用状态消息，最终提交才用整批终局回报。
