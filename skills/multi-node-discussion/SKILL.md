# 多节点讨论/辩论编排

任务需要多个执行节点相互讨论、辩论或协作深入时使用。目标不是“多个独立分支并行做完再汇总”，而是同一批讨论者常驻多轮、直接互相质询，父节点只做边界与终审。

## 适用与不适用

- 适用：多角色/多视角互相质询、回应、修正；讨论者需要常驻多轮；讨论者需要自己决定是否派生子节点做深入取证。
- 不适用：单轮并行取证、普通 map-reduce、验收节点裁决；这些用普通 spawn + child_final 即可。

## 父节点

1. **一次派生、常驻多轮**：一次 `spawn_child_nodes` 派生 N 个讨论者；父节点不要按轮次重建讨论者。讨论者自己的研究子节点不在此限，由它们在各自分支内按需派生。
2. **写清子提示词**：按下面模板写每个讨论者的 prompt；写清角色、轮次、终止条件、落盘位置。不要把本 skill 全文复制进每个 prompt。
3. **只发边界**：父节点向讨论者发三类消息：
   - 轮次开始：`send_message(to=[所有讨论者 node_id], content="Rk 开始：...")`；
   - 下一轮开始：收齐本轮全部讨论者的“轮次完成”状态消息后再发；
   - 进入终审：要求讨论者停止质询并提交。
   父节点不代转发言，不替讨论者拟定每轮质询目标；轮次话题可以给，具体攻击哪条证据由讨论者自己决定。
4. **轮次完成协议**：每个讨论者每轮结束向父节点发一条只含状态的消息（轮次、是否有新证据、是否已落盘）；父节点收齐本批 N 条后再发下一轮。不要用 `wait_all_children` 的 child_final 当轮次 barrier——常驻讨论者只会在最终提交时终局。最终提交时可以用 `wait_all_children=true` 让 child_final 一起到达。
5. **异常处置**：某讨论者暂停/失败时，按 `manage_child_nodes` 处置；不要把缺失的轮次完成状态当成已完成。
6. **终审**：父节点发“进入终审”的停止信号；终审结论由父节点自己 `submit_final_result`，不作为讨论发言。
7. **控制动作**：pause/resume/terminate 仍用 `manage_child_nodes`，不要用讨论消息代替。

## 讨论者

1. **首轮独立**：发布首轮立场前不读、不向同级索取证据；只可发轮次就绪/状态。首轮发布后必须直接质询。
2. **找同级**：用 `view_node_tree(scope="family")` 找**执行同级**的 `node_id`；同级里的验收节点不可发，自己的执行后代/后代验收节点按节点提示词的目标矩阵。
3. **直接通信**：用 `send_message(to=<同级 node_id>, content=...)` 发起质询/回应；用 `enter_wait` 等对方消息。
4. **每轮状态**：每轮结束向父节点发一条只含状态的轮次完成消息；不要只写文件等父节点转述。
5. **落盘**：发言与证据仍按任务约定落盘（追加式、编号唯一）；消息用于互动，文件用于审计。
6. **自行派生**：若你的分支有互不依赖的取证/分析子问题，自行 `spawn_child_nodes`；子节点结果以 `child_final` 回来。需要扩展时用 `coverage`，只做限定轮次可用 `focus`。
7. **收口**：收到父节点“进入终审”后停止质询，按任务要求提交 `submit_final_result`；没有终止信号不要提前提交。

## 子节点提示词模板

父节点复制后按本次任务填充：

```text
你是本次讨论的第 {i} 位讨论者「{role}」，常驻第 {rounds} 轮。
【首轮】发布前不读、不向同级索取证据；按 {evidence_path} 落盘 R1。
【通信】用 view_node_tree(scope="family") 找执行同级 node_id；用 send_message 质询/回应；用 enter_wait 等消息。
【轮次】每轮结束向父节点 {parent_id} 发一条只含状态的消息（轮次/是否有新证据/是否已落盘）；收到“进入终审”后停止并 submit_final_result。
【派生】若你的分支有互不依赖的取证/分析子问题，自行 spawn_child_nodes；可多级；结果以 child_final 回来。
【终止】{termination_rule}
【交付】{deliverable}
```

## 反模式

- 父节点每轮重新派生 8 个节点 → 得到 24 个轮次工人，不是 8 个常驻讨论者。
- 父节点把每轮攻击目标全写好 → 讨论者只执行，不讨论。
- 告诉讨论者“互不可见”，或只让它们读文件 → 没有直接通信；首轮独立只需“发布前不读/不索取证据”。
- 所有讨论者都写 `focus` 且只给单轮任务 → 没有理由派生；需要扩展时用 `coverage`。
- 用 `wait_all_children=true` 等轮次完成 → 常驻讨论者不终局，child_final 不会来；轮次用状态消息，最终提交才用 child_final。
